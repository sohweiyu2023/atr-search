# Build diagnostics

The index builder emits JSON events prefixed with `[atr-search]`. Each event has a build ID, attempt, job key, stage, level and elapsed seconds. GitHub run IDs and commit SHAs are accepted only in their expected numeric/hex formats; local builds use random IDs. Native GitHub Actions job IDs and per-step durations remain in the GitHub run UI; the builder does not call GitHub APIs to discover them.

Covered events include fetch attempts, retry delays, HTTP status, timeouts and invalid JSON; feed totals and early endings; mutually exclusive skipped-record counts (missing link, empty content, excluded static page); language counts; Pagefind durations, exit codes and byte counts; manifest/page-count and required asset validation; public status completion; and terminal success/failure. Known process panic/permission-denied patterns are reported as boolean flags. Fatal reason codes use a fixed allowlist. A failed validation prevents publication of a new status file.

`.diagnostics/build.json` is the default atomic local report, outside the published `public/` tree and ignored by Git. `--diagnostics PATH` selects another local destination. The report is replaced per invocation. In Actions, the aggregate events remain in the existing index-step log; no new external log service or artifact dependency was added. Native Actions retention continues to apply. A local report write failure emits a warning without changing a successful index build into a failure.

Broken console writes are counted in the local report without serializing the exception. Summary-file write errors produce fixed warnings rather than raw paths or exception messages; they do not replace the original build/deploy outcome. An intercepted Ctrl+C produces a cancelled terminal report and exit code 130. Fetch timeouts include urllib-wrapped timeout errors and retain the existing 60-second request deadline and four-attempt backoff. There is no new Pagefind timeout or operating-system signal handler: the existing 30-minute job deadline and native Actions cancellation/timeout state remain authoritative when the runner terminates the process before Python can finish.

The build workflow gives phases stable IDs and runs an outcome summary after a successful checkout even when subsequent phases fail. Only outcome fields enter the summary environment; step outputs are never serialized. The deployment job adds its own final outcome summary, including failed/cancelled outcomes when Actions permits the always step to run. Native action logs remain authoritative for installation, setup, upload, deployment and keepalive errors. Checkout failure, forced runner termination, job timeout or cancellation may prevent the summary/report from completing; consult the native Actions result in those cases. Validation CI already retains its native install/audit/test results; it is not changed by this patch.

Warnings are not fatal: a retried fetch can ultimately succeed; Pagefind's no-stemming notices for Chinese/Japanese are recorded as nonfatal stderr warnings. `wasm: null` in a Pagefind language manifest uses `wasm.unknown.pagefind`, rather than indicating an invalid index. Runner migration and Node deprecation notices remain in their originating Actions logs, distinct from failed steps.

Privacy boundary: no visitor queries, browser history, article titles/text/labels/links, feed URLs, raw exception messages, tracebacks, Pagefind stdout/stderr, credentials, or arbitrary environment values are printed by the added diagnostics. Only fixed event labels, numeric aggregates and validated run metadata are stored. This intentionally trades raw stack traces for safe stage/reason codes. The builder still downloads and indexes public blog content as before; this policy concerns diagnostic output.

Browser limitation: this repository contains the index builder and Actions workflows, not the Blogger theme's search JavaScript. No browser error instrumentation, analytics, telemetry endpoint or visitor logging has been introduced. Auditing browser import/search/fallback/render errors requires the current theme source separately; do not infer browser health from these offline build tests.

Local checks: `python -m unittest discover -s tests -v`. The suite includes synthetic multilingual Pagefind output and injected retry/failure, incomplete feed, skipped records, subprocess, manifest, privacy and summary cases. No live blog fetch or deployment is required.

## Local follow-up: retained safe upstream explanations (not deployed)

The deployed fd843f7 logger described above discarded response bodies and subprocess explanations. That historical detail cannot be reconstructed from counters, and no requests are replayed to recover it. The November 3 source follow-up adds `safe_evidence.py` and boundary integration; until separately published and released, it is local source/test work only.

HTTP error responses now retain bounded redacted nested explanation fields (message/reason/code/details/causes), safe correlation headers and allowlisted authentication challenge fields, alongside UTC time, duration, status/code, the sanitized feed endpoint, Python version, the current locked Pagefind version, and an explicit unavailable Node-runtime version. JSON/schema failures on successful feed payloads retain syntax/causal metadata but redact the payload and data-derived exception values. Response-read and response-close failures are separately identified without replacing the original HTTP failure. No request headers, credentials, visitor queries, article fields, arbitrary environment values or raw response bytes are persisted.

Local-only evidence goes under the diagnostics directory's `evidence/`, outside the configured public output. Each build retains at most 16 records and 128 KiB in its report; at most seven reports and seven days of reports are retained when a capture runs. Retention does not expire files while no process is running, and does not remove unrelated filenames. Raw HTTP error reads are capped at 16 KiB; success-feed reads are capped at 32 MiB. Pagefind pipes are concurrently drained with only 16 KiB per stream retained in memory before redaction, without raw temporary files. Oversize/incomplete JSON keeps only complete allowlisted explanatory fields; discarded payloads, empty/missing bodies, unavailable data, collection/depth limits and truncation are explicit. Causal chains are bounded to five exceptions. Missing language tokenizer support remains a nonfatal warning and now has a local redacted explanation.

Files use exclusive temporary creation and atomic replacement, with POSIX owner-only file/directory modes where supported. On Windows the existing user-profile/workspace ACL applies: this implementation does not change ACLs or claim a new isolation guarantee. Evidence write failures emit only a fixed aggregate warning; the original operation error still propagates. `EvidenceStore.export(destination)` writes an exclusive, bounded, re-redacted JSON support copy; it rejects the public tree, never overwrites an existing file and sends nothing. Export copies have caller-managed retention. There is no automatic artifact upload, telemetry collector, support-sharing link or console body output; public repository Actions logs are not a private evidence store.

Redaction handles sensitive JSON fields, known credential environment values and explicit canaries, credential assignments, bearer/JWT/provider token patterns, URLs, email addresses, user paths and payload assignment lines. This is a conservative allowlist/filter, not a claim that arbitrary unlabeled free text can always be classified as sensitive. Unknown structured fields are explicitly counted as redacted. Operator review remains necessary before sharing a support export. No historical explanation is fabricated when absent or discarded.

Boundary scope: the fetch transport/parser, build/schema/index validation, local Pagefind launcher/pipes, redaction/persistence/retention and local support-export code are covered. This repository has no browser theme code or user sign-in flow. GitHub Actions/OIDC authentication and deployment remain external pinned actions with their existing native logs; this local builder cannot recover provider bodies those actions did not expose or historical logs that were discarded. No workflow, permission, secret, dependency, browser, authentication or deployed artifact change accompanies this source follow-up. Hard runner termination still depends on native Actions status; the optional subprocess timeout is only exercised with synthetic processes in tests and introduces no new production timeout policy.

Production retention gap: GitHub-hosted runner files are ephemeral. The local evidence store has not been configured as a durable private CI store, and this patch deliberately adds no upload to public Actions artifacts/logs. A reviewed private retention/export destination and release authorization are separate follow-up requirements; passing local persistence tests does not establish durable production evidence retention.

## Independent-review corrections (local only)

The initial 33-test result and simple saved example did not establish privacy acceptance. Independent review reproduced encoded-secret leakage, sensitive `request.message` salvage from incomplete JSON, novel prose echoes, a partial export left after write failure, and a final serialized-size mismatch. Regression tests now cover those cases directly. Known secret variants include percent/HTML/Unicode escapes, base64/url-safe base64 and hex; declared private-field values are propagated into prose redaction. Incomplete JSON uses bounded ancestor-preserving prefix parsing rather than leaf-name regex extraction. Detected submitted-text/quoted echoes are redacted while preserving causal suffixes where possible.

Every local provider-controlled explanation/cause remains marked `review_required`: arbitrary unlabeled or multilingual free text cannot be guaranteed classified automatically. The default support export therefore withholds **all** provider prose, causes, authentication challenge text and correlation fields, retaining only fixed/numeric diagnostic metadata. `export(destination, reviewed=True)` is an explicit operator-review attestation for a bounded re-redacted full copy, not an automatic safety claim or permission to upload it. No export is sent anywhere. Persisted and memory-only records are distinguished with record sequences, per-export `persisted` flags and persistence failure metadata.

Retention now evaluates the actual final indented, encoded JSON size, counts evicted records, and explicitly truncates details if a single record cannot fit. Export write failures clean up the new partial destination after checking its file identity, while preserving a pre-existing destination. The new adversarial tests inspect the persisted JSON and both default/reviewed export modes. The deployed logger and workflow are unchanged; durable private CI retention and an approved handling policy for unverified local prose remain release gaps.

## November 4 source-only privacy continuation

This section supersedes the earlier draft policy that wrote redacted-but-unverified prose locally. Default on-disk evidence is now schema 2 **metadata only**. Body explanations, exception messages/types, authentication challenges, provider correlation IDs and arbitrary component strings stay out of automatic persistence; only fixed component names and validated/generated numeric/runtime metadata are retained. The bounded redacted detail remains in process memory, marked for review, and is lost on process exit. This is deliberate withholding, not a claim that an explanation was safely retained in full.

`retain_reviewed(sequence)` is an explicit operator-review attestation that persists a selected redacted record. The unattended builder never invokes it. `export(..., reviewed=True)` remains a separate explicit review attestation and can export reviewed memory-only detail; it does not imply that full detail was already saved in the evidence file. Per-record `persisted` and `detail_persisted`, plus retained metadata/detail sequence sets, make that distinction explicit. A failed reviewed write never claims successful detail retention. Unknown/multilingual prose and unknown encodings need no heuristic recognition to stay out of default disk/export output. Source tests verify both modes against actual files; they do not prove arbitrary prose is safe for automatic full-detail retention.

The deployed fd843f7 workflow is unchanged. Consequently this local privacy default does **not** yet change production, and does not solve durable provider-body retention on ephemeral CI. Earlier synthetic artifacts are historical snapshots; new evidence must identify its schema/policy before use.

### Durable retention assessment — no configuration performed

| Option | What it would retain | Conditions before implementation |
| --- | --- | --- |
| Current metadata-only local files | Safe diagnostic envelope; no full provider explanation | No new access; reports still disappear with hosted-runner teardown. Useful correlation, incomplete full-error retention. |
| Private encrypted object storage with narrowly scoped short-lived workload identity | Bounded redacted detail, with separate writer and support-reader roles, lifecycle cleanup and audit trail | Approve destination/provider processing, access roles, key ownership, retention/deletion semantics and cost; approve new OIDC trust/grants at action time. No destination or account is assumed to exist. |
| Dedicated private runner/collector or private workflow | Detail outside the public repository's artifacts, behind an approved access boundary | Approve runner isolation, trusted-code policy, storage encryption, reader scope and cleanup ownership. Do not repurpose the user's interactive PC or assume the current repository token can write to another private repository. |
| Client-side encrypted artifact | Ciphertext rather than plaintext on the artifact service | Requires a vetted encryption implementation, key custody/recovery and explicit storage review. Public ciphertext and metadata can be copied beyond hosting expiry, so this is not a default substitute for a private retention boundary. No keys or packages are created here. |

GitHub documents that signed-in readers of a repository can download its workflow artifacts; therefore artifacts in this public repo are not a private evidence channel: https://docs.github.com/actions/managing-workflow-runs/downloading-workflow-artifacts . OIDC can replace long-lived cloud secrets with short-lived tokens, but still requires establishing cloud-provider trust and workflow authentication: https://docs.github.com/en/actions/concepts/security/openid-connect . S3 is one illustrative private-store option, not a selected provider: encryption controls are described at https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingEncryption.html and lifecycle expiry at https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-expire-general-considerations.html . Expiry is asynchronous, so a strict deletion SLA needs separate validation, including noncurrent versions where applicable.

No artifact upload, bucket, repository, token, trust policy, key, account setting, permission grant, dependency, scheduled task or deployment is added by this assessment. Before a later release, choose a private retention/processing policy that reconciles full explanations with unclassified content; review the source privacy change and its intentional detail-loss tradeoff. Do not replay historical provider requests to fill discarded detail.

### Recovery review correction

Independent review confirmed the metadata-only default, and found that reusing a build ID could overwrite an earlier reviewed report. Each logger instance now writes a UUID-qualified `report_path`; a new instance cannot reuse the preceding instance's report filename. The seven-report/seven-day retention policy still applies. `EvidenceStore.read_retained(path)` provides a bounded schema-2 read for local inspection, rejecting oversized, invalid, symlink and public-output reports. Reading does not populate a new store, promote trust, export or transmit anything. Operator attestations remain API assertions, not evidence that an external human actually reviewed the content.

Synthetic restart tests prove that a selected reviewed explanation remains readable after a new same-ID instance captures another failure. Unreviewed explanations are **not** recoverable after process exit, and neither kind of local report is durable across hosted-runner teardown. This is a deliberate privacy tradeoff and an unresolved unattended-recovery requirement, not an implementation of full durable logging.
