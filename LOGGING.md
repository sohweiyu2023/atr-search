# Build diagnostics

The index builder emits JSON events prefixed with `[atr-search]`. Each event has a build ID, attempt, job key, stage, level and elapsed seconds. GitHub run IDs and commit SHAs are accepted only in their expected numeric/hex formats; local builds use random IDs. Native GitHub Actions job IDs and per-step durations remain in the GitHub run UI; the builder does not call GitHub APIs to discover them.

Covered events include fetch attempts, retry delays, HTTP status, timeouts and invalid JSON; feed totals and early endings; mutually exclusive skipped-record counts (missing link, empty content, excluded static page); language counts; Pagefind durations, exit codes and byte counts; manifest/page-count and required asset validation; public status completion; and terminal success/failure. Known process panic/permission-denied patterns are reported as boolean flags. Fatal reason codes use a fixed allowlist. A failed validation prevents publication of a new status file.

`.diagnostics/build.json` is the default atomic local report, outside the published `public/` tree and ignored by Git. `--diagnostics PATH` selects another local destination. The report is replaced per invocation. In Actions, the aggregate events remain in the existing index-step log; no new external log service or artifact dependency was added. Native Actions retention continues to apply. A local report write failure emits a warning without changing a successful index build into a failure.

Broken console writes are counted in the local report without serializing the exception. Summary-file write errors produce fixed warnings rather than raw paths or exception messages; they do not replace the original build/deploy outcome. An intercepted Ctrl+C produces a cancelled terminal report and exit code 130. Fetch timeouts include urllib-wrapped timeout errors and retain the existing 60-second request deadline and four-attempt backoff. There is no new Pagefind timeout or operating-system signal handler: the existing 30-minute job deadline and native Actions cancellation/timeout state remain authoritative when the runner terminates the process before Python can finish.

The build workflow gives phases stable IDs and runs an outcome summary after a successful checkout even when subsequent phases fail. Only outcome fields enter the summary environment; step outputs are never serialized. The deployment job adds its own final outcome summary, including failed/cancelled outcomes when Actions permits the always step to run. Native action logs remain authoritative for installation, setup, upload, deployment and keepalive errors. Checkout failure, forced runner termination, job timeout or cancellation may prevent the summary/report from completing; consult the native Actions result in those cases. Validation CI already retains its native install/audit/test results; it is not changed by this patch.

Warnings are not fatal: a retried fetch can ultimately succeed; Pagefind's no-stemming notices for Chinese/Japanese are recorded as nonfatal stderr warnings. `wasm: null` in a Pagefind language manifest uses `wasm.unknown.pagefind`, rather than indicating an invalid index. Runner migration and Node deprecation notices remain in their originating Actions logs, distinct from failed steps.

Privacy boundary: no visitor queries, browser history, article titles/text/labels/links, feed URLs, raw exception messages, tracebacks, Pagefind stdout/stderr, credentials, or arbitrary environment values are printed by the added diagnostics. Only fixed event labels, numeric aggregates and validated run metadata are stored. This intentionally trades raw stack traces for safe stage/reason codes. The builder still downloads and indexes public blog content as before; this policy concerns diagnostic output.

Browser limitation: this repository contains the index builder and Actions workflows, not the Blogger theme's search JavaScript. No browser error instrumentation, analytics, telemetry endpoint or visitor logging has been introduced. Auditing browser import/search/fallback/render errors requires the current theme source separately; do not infer browser health from these offline build tests.

Local checks: `python -m unittest discover -s tests -v`. The suite includes synthetic multilingual Pagefind output and injected retry/failure, incomplete feed, skipped records, subprocess, manifest, privacy and summary cases. No live blog fetch or deployment is required.
